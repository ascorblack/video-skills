# Автоматические проверки готового файла [Стек]

Проверки ниже ловят то, что можно измерить. Они не заменяют просмотр: полноразмерные кадры на каждом стыке и в каждом моменте действия, затем один полный просмотр ролика со звуком [Видео] [3D].

## `scripts/qa.sh <video> [out-dir]`

Один запуск — одна папка с результатами проверки:

| Результат | На что смотреть |
|---|---|
| `summary.txt` | кодек, размер, fps, формат пикселей, длина видео и звука, громкость, количество чёрных и застывших участков |
| `probe.json` | полный вывод ffprobe — всё, чего не видно в сводке |
| `detect.log` | чёрные участки ≥ 0.1 с (`blackdetect`). Ожидаемо: уход в чёрное, запланированный в таблице шотов. Неожиданно: чёрное в самом начале или конце либо чёрная вспышка на стыке — кадр захвачен до готовности сцены |
| `detect.log` | застывшие участки ≥ 0.5 с (`freezedetect`). Удержания для чтения ожидаемы [Визуал]; замирание посреди анимированного шота — библиотека не перемоталась, ассет не загрузился или в переход подали стоп-кадры |
| `loudness.log` | интегральная громкость EBU R128, LRA, истинный пик — измерены на закодированном файле, потому что кодирование поднимает пики [Звук]. Целевые значения — `video-audio`, `mixing.md` |
| `sheet.jpg` | 16 кадров равномерно по ролику: общий ритм, сцена, которая так и не появилась, кадр в чужом стиле |
| `first.png`, `last.png` | начальный и конечный кадры в полном размере: не чёрные, не прозрачные, не загруженные наполовину |

Затем сверьте с планом:

- размер и fps как в заказе (вертикальный короткий ролик — 1080×1920, а не повёрнутый 1920×1080);
- `yuv420p` для всего, что будут смотреть на телефонах и в браузерах;
- звуковая дорожка есть и такой же длины, что видео (разница в десятки миллисекунд — служебная тишина кодировщика [Звук]);
- длина ролика равна суммарной длине из таблицы шотов.

## `scripts/compare-renders.sh <a> <b>`

Повторяемость при перемотке: два рендера одного исходника из чистых процессов должны декодироваться в одинаковые кадры. Скрипт сначала сравнивает размер, частоту кадров, их число, длительность и время показа каждого кадра (`TIMING DIFFERS` или `FRAME TIMES DIFFER` останавливают его), затем контрольные суммы декодированных кадров, перечисляет номера различающихся кадров и минимальный PSNR.

- `IDENTICAL` — сцена детерминирована.
- Несколько кадров сильно ниже 50 дБ — утечка: реальное время, случайность без фиксированного seed, библиотека со своим тикером, поздно загрузившийся ассет. Смотрите первый указанный кадр; следующие за ним кадры внутри того же GOP отличаются лишь потому, что кодировщик распространяет изменение.
- Все кадры слегка различаются, PSNR выше ~50 дБ — обычно аппаратный кодировщик, который не даёт побитового совпадения между запусками; повторите с одинаковыми настройками программного кодировщика или отрендерите PNG-кадры, чтобы отличить это от утечки.
- Один раз запустите с кадрами, полученными в другом порядке (другое число воркеров или диапазон с началом посреди шота): состояние, которое накапливается от кадра к кадру, проходит первое сравнение и проваливает это.

## Отдельные команды, когда скрипт избыточен

```bash
# what the file is
ffprobe -v error -show_entries format=duration:stream=codec_name,width,height,r_frame_rate,pix_fmt -of json out/final.mp4
# one frame every 2 s for a quick look
ffmpeg -hide_banner -i out/final.mp4 -vf "fps=1/2,scale=320:-2" out/qa/sample_%03d.jpg
# three frames around a join at 12.4 s: end of shot, middle of the transition, start of the next [Visual]
for t in 12.0 12.4 12.8; do ffmpeg -hide_banner -loglevel error -ss $t -i out/final.mp4 -frames:v 1 out/qa/join_$t.png; done
# loudness and true peak of the encoded file
ffmpeg -hide_banner -nostats -i out/final.mp4 -vn -af ebur128=peak=true -f null - 2>&1 | tail -12
```

## Чего автоматические проверки не видят

Обрезанный или нечитаемый текст, линия сквозь блок, неверное число, подпись, которая исчезает раньше, чем её дочитали, курсор, замешкавшийся над не той кнопкой, рассинхрон речи, следствие до причины на стыке, GPU-текстура, испорченная лишь в отдельных кадрах. Это проверяют глазами на полноразмерных кадрах и при воспроизведении; правила для каждого случая — в `video-design`, `video-ui-capture`, `video-3d-animation` и `video-audio`. Для WebGL-сцен смотрите кадры экспортированного файла, а не интерактивный предпросмотр.
